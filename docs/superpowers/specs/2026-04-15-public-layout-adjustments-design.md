# 公开站点首页与详情页布局调整设计

## 背景

生产站点已经迁移到 `tc.b8water.com:8088`，现在需要继续调整公开前台与后台可维护能力，重点集中在首页模块重排、首页图片展示、导航与页脚样式、以及详情页全宽化。

本次工作必须先在独立分支中完成，待用户确认效果后再考虑合并到 `main`。

## 目标

1. 让首页结构更贴近用户提供的视觉要求：
   - 移除首页所有 eyebrow 风格标题
   - 把首页案例列表从 `split-grid` 中拆出成独立模块
   - 把首页左侧“解决方案说明”改成一张可替换图片
   - 在首页正文 section 前新增两张上下排列、宽度 `100%` 的全宽大图
2. 让后台能维护这些图片，而不是写死在模板里。
3. 统一调整公开站点的若干公共样式与详情页布局。

## 非目标

1. 不改动站点信息架构、URL 规则或内容模型的业务含义。
2. 不在本轮引入新的前端框架或重写公开站点渲染方式。
3. 不在用户确认前合并到 `main`。

## 设计决策

### 1. 首页两张全宽大图复用现有站点设置字段

首页新增的两张全宽大图，直接复用现有站点设置中的：

- `home_banner_media_id`
- `home_banner_secondary_media_id`

原因：

1. 这两个图位已经存在于 `site_settings`、仓储层与 AdminJS 资源定义中。
2. 用户明确希望“可更换”，复用已有图位可以避免再增加两个冗余字段。
3. 这两个图位原本主要用于首页视觉位，语义仍然成立。

展示方式：

- 在首页 Hero 后、后续常规 `section` 前插入一个新的全宽图片区块。
- 两张图按“上下排列”的方式展示。
- 每张图宽度占满可视内容区域。

### 2. 新增首页解决方案主图字段

首页 `split-grid` 左侧不再展示“解决方案列表卡片”，改为一张后台可维护的图片，因此新增一个单独字段：

- `home_feature_media_id`

该字段挂在 `site_settings` 上，原因是它属于首页长期视觉配置，而不是某条具体内容记录。

落点：

1. `schema.sql` 与迁移逻辑新增列。
2. `site-repository` 读写与站点素材关联补齐。
3. `public-site-service` 把该图转换成公开可渲染资产。
4. 传统中文后台站点设置表单补出该字段。
5. AdminJS 站点设置资源补出该字段。

### 3. 首页模块重排

首页调整后的结构如下：

1. Hero 保留，但首页不再渲染 eyebrow 文案。
2. Hero 后插入“两张上下排列的全宽图片模块”。
3. 保留数据统计区块。
4. 保留产品区块，但首页内所有 eyebrow/card eyebrow 文案移除。
5. “案例列表”从原 `split-grid` 右侧拆出，做成独立模块，位置放在 `split-grid` 之前。
6. `split-grid` 改为 `0.8fr 1.2fr`：
   - 左侧：首页解决方案主图
   - 右侧：新闻资讯列表
7. CTA 区块保留主体内容，但删除 eyebrow 文案。

这样可以满足用户提出的“案例不再包含在 split-grid 中”和“split-grid 左侧改图”的要求，同时尽量少动现有数据流。

### 4. 首页 eyebrow 的处理范围

“首页删除所有关于 eyebrow 的标题内容”按首页内所有 eyebrow 型标签处理，包括：

- `hero.eyebrow`
- `.section-heading` 内的 `.eyebrow`
- 首页卡片中的 `.card__eyebrow`
- CTA 区中的 `.eyebrow`

实现上优先删掉首页模板中的对应输出，而不是只用 CSS 隐藏。这样更干净，也避免留下无意义 DOM。

### 5. 公共样式调整

按用户要求调整以下公开样式：

1. `.site-nav ul` 的桌面间距从 `2rem` 改为 `5em`
2. `.site-footer__grid` 的桌面列宽从 `2fr 1fr 1fr` 改为 `1.5fr 1.5fr 1fr`
3. 删除 `.rich-text img` 规则块
4. `split-grid` 桌面列宽改为 `0.8fr 1.2fr`
5. 为首页案例独立模块增加新的 CSS 命名，而不是继续复用 `split-grid`

### 6. 页脚与详情页布局

页脚：

- 删除 `footer-cta` 的输出内容，而不是仅通过样式隐藏。

详情页：

- 页面、产品、解决方案、案例详情统一去掉 `detail-aside`
- 内容区统一改成全宽策略

虽然用户最初点名了 `about` 与 `product-detail` 的容器代码，但后续已确认希望把页面/产品/解决方案/案例这几类详情页统一处理，因此设计上会收敛成一套共享布局。

为了保持模板一致性，优先采用共享 class 或统一容器写法实现“`max-width: 100%; padding: 0;`”的效果，而不是在多个模板里复制相同内联样式；如果个别模板必须保留显式内联样式，会只在最少范围内使用。

## 影响范围

### 前台模板

- `src/views/public/home.ejs`
- `src/views/public/page.ejs`
- `src/views/public/product-detail.ejs`
- `src/views/public/solution-detail.ejs`
- `src/views/public/case-detail.ejs`
- `src/views/partials/public-footer.ejs`
- 可能涉及 `src/views/partials/hero.ejs`

### 样式

- `public/css/public.css`

### 数据与服务层

- `src/lib/schema.sql`
- `src/lib/migrations.js`
- `src/repositories/site-repository.js`
- `src/services/public-site-service.js`

### 后台维护入口

- 传统后台站点设置表单
- AdminJS 站点设置资源

## 数据流

### 首页全宽双图

1. 管理员在站点设置中维护两张首页 Banner 图
2. `site-repository` 读取 `home_banner_media_id` / `home_banner_secondary_media_id`
3. `public-site-service` 把它们转换为公开素材对象
4. 首页模板在 Hero 后渲染上下两张全宽图片

### 首页解决方案主图

1. 管理员在站点设置中维护 `home_feature_media_id`
2. 站点服务层将其暴露为公开资产
3. 首页 `split-grid` 左侧直接渲染该图
4. 若未配置图片，则保留可接受的空态/占位策略，避免模板报错

## 错误处理与兼容策略

1. 新图位为空时，页面必须仍可正常渲染，不得因为缺图报错。
2. 后台表单提交时，继续复用现有媒体跨站校验逻辑，确保不能引用其他站点不允许的素材。
3. 样式改动只限公开站点，不影响后台样式。
4. 详情页去侧栏后，下载按钮等原侧栏内容不再展示，这是用户显式要求，不做隐藏式保留。

## 测试策略

1. 保持现有 `node --test` 基线通过。
2. 为首页渲染与站点设置补充/更新测试，覆盖：
   - 首页案例列表已脱离 `split-grid`
   - 首页双图模块渲染
   - 首页解决方案主图渲染
   - 首页不再输出 eyebrow 文案
3. 为详情页测试补充/更新：
   - 页面/产品/解决方案/案例详情页不再渲染 `detail-aside`
   - 相关容器输出符合新的全宽布局
4. 视需要增加最小化模板断言，避免只靠人工检查。

## 实施顺序建议

1. 先把基线缺失的 AdminJS 依赖文件正式纳入当前功能分支，确保工作区稳定。
2. 再补 `site_settings` 新字段与后台维护入口。
3. 然后调整首页模板与公共样式。
4. 最后统一处理详情页布局并更新测试。

## 风险

1. 当前源码主线存在一次“提交文件与实际工作树不一致”的情况，后续提交时需要特别注意只保留本分支真正需要的 AdminJS 基线补齐与本次前台调整。
2. 首页两张全宽图复用现有 Banner 字段后，原 Hero 的轮播职责会发生变化；实现时需要确保 Hero 仍然能以单图或无图模式正常工作。
3. 页脚 CTA 与详情侧栏删除后，若原来承担某些下载入口，需要确认这是预期变更；按当前需求，本轮视为明确移除。
